# OpenCode MCP fallback for Pi

On `session_start`, this globally loaded extension reads **only** `cwd/opencode.json` (strict JSON) and registers its `mcp.servers` for the current session. If `cwd/.pi/mcp.json` exists—even empty or invalid—it imports nothing. A global Pi `mcp.json` does not block the fallback; native entries with the same names still take precedence in Pi. It never edits MCP configuration or replaces `/mcp`. Use `/reload` after editing the file. Shell `pi mcp list` does not load extensions and therefore cannot show these registrations; use `/mcp` in a session.

Project trust is required: Pi's denied/untrusted contexts are skipped. In bare directories where Pi otherwise considers projects trusted by default, the extension checks Pi's native trust store and asks for explicit approval if no decision is saved. Approval **trusts the project folder for all Pi project settings and resources**, not just MCP; it is remembered in Pi's native trust store. Without the interactive TUI (including RPC startup), use `/trust` first or launch Pi with `--approve` (`-a`) for a session-only override. RPC startup cannot answer a trust dialog before its input loop starts. `--no-approve` (`-na`) always skips.

Local `command` arrays become `command` and `args`, `environment` becomes `env`, and remote `url`/`headers` are passed to Pi's streamable HTTP transport. `{env:NAME}` becomes Pi's `${NAME}` in env, headers, and OAuth `clientSecret`; command, args, URL and cwd resolve from the process environment at import time (missing variables skip that server). `timeout` milliseconds become Pi's per-request seconds. A `startup` timeout applies to *all* requests, not just startup, and emits a warning. `oauth:false` cannot disable Pi's native OAuth-on-401 behavior and emits a warning; an OAuth object can supply `clientId`, `clientSecret`, `scope`, `callbackPort`, and `callbackUrl`. Legacy SSE is unsupported; `/stream` URLs are not rewritten. Bad entries warn and do not prevent other servers loading.
